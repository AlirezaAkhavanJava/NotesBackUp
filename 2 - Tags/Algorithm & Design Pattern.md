

---

### **Algorithm**

- **Definition:** A step-by-step procedure to solve a **specific problem**.
    
- **Focus:** _Logic and computation_.
    
- **Example:** Sorting an array (QuickSort, MergeSort), finding the shortest path in a graph (Dijkstra).
    
- **Nature:** Concrete, usually mathematical or computational.
    
- **Question it answers:** _"How do I solve this problem efficiently?"_
    

---

### **Design Pattern**

- **Definition:** A **reusable solution template** for a **common software design problem**.
    
- **Focus:** _Structure, organization, and interaction of code_.
    
- **Example:** Singleton (ensures one instance), Observer (notify changes to multiple objects), Factory (object creation).
    
- **Nature:** Abstract, conceptual, not tied to one problem instance.
    
- **Question it answers:** _"How do I organize my code to solve recurring design challenges?"_
    

---

**Quick analogy:**

- Algorithm = recipe for **making a cake** (specific steps).
    
- Design pattern = **style of kitchen organization** (how you structure your tools and workflow so recipes are easier to manage).

> 	Think of it like this:
>
> - **Algorithm:** “How do I make the cake?” → the steps of mixing, baking, decorating.
  >  
> - **Design Pattern:** “How do I arrange my kitchen and tools so I can make any cake easily?” → where the oven goes, where the bowls live, how ingredients are organized
