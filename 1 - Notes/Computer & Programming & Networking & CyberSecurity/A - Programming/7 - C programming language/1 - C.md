# Defining C (from a Java developer's mental model)

Since you're coming from Java, the fastest way to *define* C is to describe its **building blocks** — the internals you actually write code with — and map each to the closest Java concept so you can anchor it. I'll also point out where the analogy **breaks**, because that's where C's real identity lives.

---

## 1. The Program Structure

### In Java
A program = a collection of **classes**, each containing **fields** and **methods**. Execution starts at `public static void main(String[] args)` inside some class.

### In C
A program = a collection of **functions** (mostly free-standing, not attached to anything) plus **global variables**. Execution starts at `int main(void)` — a plain function, not inside any class.

```c
#include <stdio.h>   // like an import, but it's a textual include

int globalCounter = 0;        // global variable (like a static field, but truly global)

int add(int a, int b) {       // a function (like a static method)
    return a + b;
}

int main(void) {              // entry point
    int result = add(2, 3);
    printf("%d\n", result);
    return 0;
}
```

**Key mental shift:** there are **no classes**. Functions and data are separate. You group related functions by convention (naming, header files), not by language syntax.

---

## 2. The Core Internals (the "classes and methods" equivalent)

| Java concept | C equivalent | Notes |
|---|---|---|
| Class | *(none)* | Use a `struct` + free functions in a `.c`/`.h` pair |
| Object / instance | A `struct` variable | Just a chunk of memory with named fields |
| Method | Function | Not bound to data; you pass the struct explicitly |
| Field | Struct member | Accessed with `.` or `->` |
| `this` | *(none)* | You pass a pointer yourself, e.g. `foo(&obj)` |
| Interface | Function pointer table / header contract | Manual, no language support |
| Package | Header file + naming convention | No real namespacing |
| `static` method | Function | Default for functions |
| `static` field | Global or file-scope variable | `static` at file scope = private to that file |

### The closest thing to a "class": a struct + functions

```c
// "class" definition
typedef struct {
    int x;
    int y;
} Point;

// "methods" — take a pointer to the struct
void point_move(Point *p, int dx, int dy) {
    p->x += dx;
    p->y += dy;
}

int point_sum(const Point *p) {
    return p->x + p->y;
}

// usage
Point p = {1, 2};
point_move(&p, 3, 4);
```

So a "C object" is just a struct, and a "C method" is a function whose first argument is a pointer to that struct. This is the pattern behind essentially every C library (including the Linux kernel's object model).

---

## 3. Types — the Type System

### Java
Primitives (`int`, `double`, `boolean`, `char`) + reference types (classes, arrays, interfaces). All objects are references; primitives are values.

### C
Everything is a **value** unless you explicitly use a pointer. The type system is:

- **Primitive types:** `char`, `short`, `int`, `long`, `float`, `double`, `long long`, `_Bool`
- **Derived types:** pointers (`int *`), arrays (`int[10]`), functions (`int (*)(int)`)
- **User-defined:** `struct`, `union`, `enum`, `typedef`

**Critical differences from Java:**
- **No `boolean`** in classic C — `0` is false, everything else is true (C99 added `_Bool`/`stdbool.h`).
- **No `String` type** — strings are just `char` arrays terminated by `\0`.
- **No automatic boxing, no generics, no autoboxing, no `Object` superclass.**
- **Sizes are implementation-defined** — `int` is *usually* 4 bytes, but the standard only guarantees minimums.
- **Pointers are first-class values** — the heart of the language.

---

## 4. Memory Model (the big one)

### Java
- Stack for primitives and references; heap for objects.
- Garbage collector reclaims heap memory.
- No pointer arithmetic; references are opaque.
- `null` is a safe-ish absent reference.

### C
- **Stack:** local variables, function call frames. Freed automatically on return.
- **Heap:** obtained via `malloc`/`calloc`/`realloc`, freed with `free`. **You** are the garbage collector.
- **Static/global:** fixed at program start.
- **Pointers are addresses** — you can do arithmetic on them (`p + 1` moves by `sizeof(*p)` bytes).
- **`NULL` is just `0`** — dereferencing it is undefined behavior, not a nice exception.

```c
int *arr = malloc(10 * sizeof(int));  // heap allocation
if (arr == NULL) { /* handle failure */ }
arr[0] = 42;
free(arr);                            // you must free it
```

**Mental shift:** In Java the JVM owns memory. In C, *you* own memory, and the language trusts you completely — including to make mistakes.

---

## 5. Functions in Detail

- Functions are **top-level**, not inside anything.
- Declared in a **header** (`.h`), defined in a **source file** (`.c`).
- **Pass-by-value always** — to mutate, you pass a pointer.
- **No overloading** — one name, one signature.
- **No default arguments.**
- **No closures, no lambdas** (until C23-ish and even then minimal).
- **Function pointers** exist and are used heavily (callbacks, vtables-by-hand).

```c
// header: point.h
typedef struct Point Point;
void point_move(Point *p, int dx, int dy);

// source: point.c
#include "point.h"
struct Point { int x, y; };
void point_move(Point *p, int dx, int dy) { p->x += dx; p->y += dy; }
```

The `header`/`source` split is C's answer to Java's `interface`/`class` split — but it's textual, manual, and has no enforcement beyond the linker.

---

## 6. Compilation & "Runtime"

### Java
`javac` → `.class` bytecode → JVM loads, verifies, JIT-compiles, runs, GCs.

### C
`gcc`/`clang` → **preprocessor** → **compiler** → **assembler** → **linker** → native executable.

- **Preprocessor:** `#include`, `#define`, `#ifdef` — textual substitution *before* compilation. (Java has nothing like this.)
- **Compiler:** produces object files (`.o`), one per `.c`.
- **Linker:** combines object files + libraries (libc, your own) into one executable.
- **Runtime:** essentially `libc` + the OS loader. No VM, no bytecode, no JIT, no GC.

---

## 7. Error Handling

### Java
Exceptions (`try`/`catch`/`finally`, checked exceptions), stack traces.

### C
- **Return codes** (e.g., `-1` or `NULL` on failure) — the dominant style.
- **`errno`** — a global error number set by library calls.
- **`setjmp`/`longjmp`** — a crude non-local jump, rarely used.
- **No exceptions, no stack traces** (unless you add a library).
- **Undefined behavior** for many mistakes — the program may crash, corrupt data, or appear to work.

---

## 8. The Preprocessor (no Java equivalent)

```c
#define MAX 100
#define SQUARE(x) ((x) * (x))   // macro, not a function

#include "myheader.h"
#include <stdio.h>

#ifdef DEBUG
    printf("debug\n");
#endif
```

This is textual, untyped, and error-prone — but powerful and central to C's style.

---

## 9. What C *Is*, Summarized

> **C is a small, procedural, statically typed, compiled language where the programmer has direct control over memory through pointers, the program is built from free functions and structs rather than classes, and there is essentially no runtime beyond the C standard library and the operating system.**

### The internals you actually write with:
- **Functions** (the unit of behavior) — like Java's static methods, but standalone.
- **Structs** (the unit of data) — like Java classes with only public fields and no methods.
- **Pointers** (the unit of indirection) — like Java references, but arithmetic-capable and unsafe.
- **Headers + source files** (the unit of modularity) — like Java's interface/class split, but textual.
- **`malloc`/`free`** (the unit of dynamic memory) — like `new`, but you also `delete` by hand.
- **The preprocessor** (the unit of metaprogramming) — no real Java analog.

### The mental model shift from Java:
| Java assumption | C reality |
|---|---|
| Everything is an object | Nothing is an object; data and behavior are separate |
| GC handles memory | You handle memory |
| References are safe | Pointers are raw addresses |
| Exceptions for errors | Return codes and `errno` |
| JVM provides runtime | OS + libc is the runtime |
| Write once, run anywhere | Write once, recompile everywhere |
| Strong safety net | You are the safety net |

That last row is really the essence of C: it gives you the machine, and it trusts you to be careful.
