


A standard Spring Boot project (typically generated by [Spring Initializr](https://start.spring.io)) follows Maven/Gradle's conventional directory layout. Here's the breakdown:

```
my-spring-boot-app/
├── src/
│   ├── main/                          ← production code
│   │   ├── java/
│   │   │   └── com/example/demo/
│   │   │       ├── DemoApplication.java
│   │   │       ├── controller/
│   │   │       ├── service/
│   │   │       ├── repository/
│   │   │       ├── model/  (or entity/)
│   │   │       └── config/
│   │   └── resources/                 ← non-Java files
│   │       ├── application.properties (or .yml)
│   │       ├── application-dev.properties
│   │       ├── application-prod.properties
│   │       ├── static/
│   │       ├── templates/
│   │       ├── META-INF/
│   │       └── db/  (migrations, optional)
│   └── test/                          ← test code
│       ├── java/
│       │   └── com/example/demo/
│       │       └── DemoApplicationTests.java
│       └── resources/
│           └── application-test.properties
├── target/  (Maven) or build/ (Gradle)  ← compiled output
├── pom.xml  (Maven) or build.gradle (Gradle)
└── .mvn/  mvnw  mvnw.cmd  (Maven wrapper, optional)
```

---

## `src/main/` — Production Code Root

Everything that goes into your **deployed application** lives here. It has two subfolders:

### `src/main/java/` — Java Source Code

Contains your application's `.java` files, organized by package.

**Key convention:** The main class (with `@SpringBootApplication`) sits at the **root package**, and all other packages are **sub-packages** of it. This is critical because `@SpringBootApplication` triggers component scanning starting from its own package downward.

```java
// src/main/java/com/example/demo/DemoApplication.java
@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

Typical package layout inside:

| Package | Responsibility |
|---|---|
| `controller/` | REST endpoints, request handling (`@RestController`) |
| `service/` | Business logic (`@Service`) |
| `repository/` | Data access (`@Repository`, Spring Data JPA) |
| `model/` or `entity/` | Domain objects, JPA entities |
| `dto/` | Data Transfer Objects for API payloads |
| `config/` | `@Configuration` classes |
| `exception/` | Custom exceptions & handlers |

---

### `src/main/resources/` — Non-Java Files

Everything that isn't Java but needs to be on the **classpath at runtime**.

#### 1. `application.properties` / `application.yml`
The main configuration file. Spring Boot reads it automatically.

```properties
# application.properties
server.port=8081
spring.datasource.url=jdbc:postgresql://localhost:5432/mydb
spring.jpa.hibernate.ddl-auto=update
```

Or YAML equivalent (`application.yml`):

```yaml
server:
  port: 8081
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/mydb
```

#### 2. Profile-specific files
Override defaults per environment:

- `application-dev.properties` → activated with `--spring.profiles.active=dev`
- `application-prod.properties`
- `application-test.properties`

#### 3. `static/`
Serves **static web content** directly at the root URL. Files here are served as-is.

```
static/
├── index.html     → http://localhost:8080/index.html
├── css/style.css  → http://localhost:8080/css/style.css
├── js/app.js
└── images/logo.png
```

#### 4. `templates/`
Holds **server-side rendered templates** (Thymeleaf, FreeMarker, Mustache). These are processed by a template engine before being sent to the browser.

```
templates/
├── index.html
├── user/profile.html
└── fragments/header.html
```

> **Note:** `static/` = raw files; `templates/` = rendered views. They are not the same.

#### 5. `META-INF/`
Metadata for the JAR. Often contains:
- `META-INF/resources/` — additional static resources
- `META-INF/spring.factories` (older Boot) or `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` (Boot 3+) — for auto-configuration in libraries
- `META-INF/spring-configuration-metadata.json`

#### 6. `db/` (optional)
Database migration scripts (Flyway or Liquibase):

```
resources/db/migration/
├── V1__create_users.sql
└── V2__add_orders.sql
```

#### 7. Other common files
- `banner.txt` — custom startup banner
- `logback-spring.xml` — logging configuration
- `messages.properties` — i18n messages
- `import.sql` — seed data (Hibernate)
- `schema.sql`, `data.sql` — initial schema/data scripts

---

## `src/test/` — Test Code Root

Mirrors `main/` for test-specific code.

- `src/test/java/` — JUnit / Mockito tests
- `src/test/resources/` — test-only config (`application-test.properties`, test fixtures)

Spring Boot's test slice annotations (`@WebMvcTest`, `@DataJpaTest`, `@SpringBootTest`) use this folder.

---

## How Classpath Loading Works at Runtime

```
target/classes/              ← compiled Java  (from src/main/java)
target/classes/              ← copied resources (from src/main/resources)
```

Maven/Gradle copies everything in `resources/` into the classpath root. So:

| File on disk | Accessible as |
|---|---|
| `resources/application.properties` | `classpath:/application.properties` |
| `resources/static/logo.png` | `classpath:/static/logo.png` → served at `/logo.png` |
| `resources/templates/home.html` | `classpath:/templates/home.html` |

---

## Summary Table

| Path | Purpose |
|---|---|
| `src/main/java/` | Production Java source code |
| `src/main/resources/` | Non-Java runtime files (config, static, templates, SQL) |
| `src/main/resources/static/` | Raw static web assets served directly |
| `src/main/resources/templates/` | Server-rendered view templates |
| `src/main/resources/application.properties` | Main app configuration |
| `src/test/java/` | Test source code |
| `src/test/resources/` | Test-only config and fixtures |
| `target/` or `build/` | Compiled output (never edit manually) |
| `pom.xml` / `build.gradle` | Build & dependency configuration |

---

## Key Rules to Remember

1. **The main class must be in the root package** so component scanning covers everything below it.
2. **`application.properties`/`yml` is picked up automatically** — no registration needed.
3. **`static/` is for raw files, `templates/` is for rendered views.**
4. **Anything in `resources/` is on the classpath**, so load it via `ClassPathResource` or `@Value("classpath:...")`.
5. **Don't put production-only and test-only files in the same folder** — use `test/resources` for test configs.
