


# Java NIO.2 File API – Full Teaching Guide  
*(Java 7+ – `java.nio.file` package)*

---

## 1. Why Was NIO.2 Created?

> **Problem with `java.io.File` (Old Way)**

```java
File file = new File("data.txt");
file.createNewFile(); // Can fail silently
file.delete();        // No feedback if file didn't exist
```

### Problems:
| Issue | Explanation |
|------|-------------|
| **Mutable** | You can do `file = new File("..")` → hard to track |
| **No atomic operations** | `createNewFile()` may fail halfway |
| **Poor error handling** | Throws `IOException` but no context |
| **No symbolic link support** | Can't distinguish soft/hard links |
| **No file tree walking** | You write `listFiles()` recursively → error-prone |
| **No metadata** | Can’t read owner, permissions easily |

---

> **NIO.2 Solution: `Path` + `Files` = Safe, Modern, Powerful**

---

## 2. Core Concepts – Explained Like a Teacher

---

### 1. `Path` – The "Address" of a File

> **Think of `Path` as a GPS location** — it **knows where** a file/folder is, but **does nothing** by itself.

```java
Path path = Paths.get("src", "main", "data.txt");
```

#### Break it down:
| Part | Meaning |
|------|--------|
| `Paths.get()` | Factory method (like `String.valueOf()`) |
| `"src", "main", "data.txt"` | Varargs → joins with correct separator (`/` or `\`) |

#### Key: `Path` is **immutable**
```java
Path p1 = Paths.get("a/b");
Path p2 = p1.resolve("c"); // p1 stays "a/b", p2 = "a/b/c"
```

> **Analogy**: Like `String` — `s1.toUpperCase()` doesn’t change `s1`.

---

### 2. `Files` – The "Worker" That Does the Job

> **Think of `Files` as a construction crew** — it **uses the `Path` address** to **build, read, delete, copy**.

```java
Files.createFile(path);     // Crew builds a new file
Files.readAllLines(path);   // Crew reads content
```

> **Never do `new Files()`** → All methods are `static`

---

## 3. `Path` Methods – Full Explanation with Examples

| Method | What It Does | Example |
|-------|--------------|--------|
| `getFileName()` | Last part | `data.txt` |
| `getParent()` | Folder above | `src/main` |
| `getRoot()` | Drive or `/` | `C:\` or `/` |
| `toAbsolutePath()` | Full path from root | `C:\project\src\main\data.txt` |
| `resolve("child")` | Append path | `src/main + logs → src/main/logs` |
| `relativize(other)` | "How to go from me to you?" | `a/b relativize a/b/c/d → ../..` |
| `normalize()` | Remove `.` and `..` | `/a/./b/../c → /a/c` |

#### Live Example:
```java
Path p = Paths.get("/home/user/../user/./docs/data.txt").normalize();
System.out.println(p); // → /home/user/docs/data.txt
```

> **Why `normalize()`?**  
> Prevents path traversal attacks: `../../etc/passwd` → becomes safe.

## 4. `Files` – Reading & Writing (Step-by-Step)

---

### Reading Files – 3 Ways

#### 1. `readAllBytes()` – For Small Files
```java
byte[] data = Files.readAllBytes(path);
String content = new String(data, StandardCharsets.UTF_8);
```
> **Use when**: File < 1 MB  
> **Warning**: Loads **entire file in memory**

---

#### 2. `readAllLines()` – For Text Files
```java
List<String> lines = Files.readAllLines(path);
```
> Returns `List<String>` — easy to loop

---

#### 3. `Files.lines()` – For **Large Files** (Best!)
```java
try (Stream<String> stream = Files.lines(path)) {
    stream
        .filter(line -> line.contains("ERROR"))
        .map(String::toUpperCase)
        .forEach(System.out::println);
}
```
> **Why best?**
> - **Lazy loading** → reads line-by-line
> - **Auto-closes** with `try-with-resources`
> - Works with **gigabyte-sized logs**

---

### Writing Files

#### 1. Write Bytes
```java
Files.write(path, "Hello".getBytes());
```

#### 2. Write Lines
```java
List<String> lines = Arrays.asList("Log 1", "Log 2");
Files.write(path, lines, StandardOpenOption.APPEND);
```

#### 3. Buffered Writer (Best for Many Writes)
```java
try (BufferedWriter writer = Files.newBufferedWriter(path, StandardOpenOption.CREATE)) {
    writer.write("Line 1\n");
    writer.write("Line 2\n");
}
```
> **Why buffered?**  
> Writing 1 byte at a time = slow  
> Buffered = collects data → writes in chunks → **100x faster**

## 5. Directory Operations – Explained

---

### `Files.list()` – List Immediate Children
```java
try (Stream<Path> entries = Files.list(dirPath)) {
    entries
        .filter(Files::isRegularFile)
        .filter(p -> p.toString().endsWith(".java"))
        .forEach(System.out::println);
}
```

---

### `Files.walk()` – Recursive Search
```java
Files.walk(Paths.get("src"), 3)  // max depth = 3
     .filter(Files::isRegularFile)
     .forEach(System.out::println);
```

> **Use case**: Find all `.java` files in project

---

### `Files.find()` – Search with Condition
```java
Files.find(
    startPath,
    10,
    (path, attrs) -> attrs.isRegularFile() 
                  && path.toString().endsWith(".log")
                  && attrs.size() > 1000
)
.forEach(System.out::println);
```

> **Like SQL WHERE clause for files**

---

## 6. File Tree Walking with `SimpleFileVisitor`

> **Use when**: You want to **copy**, **delete**, or **search** an entire folder.

```java
Files.walkFileTree(rootDir, new SimpleFileVisitor<Path>() {

    @Override
    public FileVisitResult visitFile(Path file, BasicFileAttributes attrs) {
        System.out.println("Found: " + file);
        if (file.toString().endsWith(".tmp")) {
            Files.delete(file); // Clean temp files
        }
        return FileVisitResult.CONTINUE;
    }

    @Override
    public FileVisitResult postVisitDirectory(Path dir, IOException exc) {
        System.out.println("Finished scanning: " + dir);
        return FileVisitResult.CONTINUE;
    }

    @Override
    public FileVisitResult visitFileFailed(Path file, IOException exc) {
        System.err.println("Cannot access: " + file);
        return FileVisitResult.SKIP_SUBTREE;
    }
});
```

> **Real use**: Antivirus scan, backup tool, log cleaner

## 7. Symbolic & Hard Links

| Type | Explanation | Command |
|------|-------------|--------|
| **Symbolic Link** | Shortcut (points to path) | `ln -s target link` |
| **Hard Link** | Second name for same file | `ln target link` |

```java
Path target = Paths.get("real.txt");
Path symlink = Paths.get("shortcut.txt");

Files.createSymbolicLink(symlink, target);  // Soft
Files.createLink(symlink, target);          // Hard (same OS only)
```

> **Use case**:  
> - Symlink: `/logs/latest → /logs/2025-10-29.log`  
> - Hard link: Backup without duplicating data

## 8. File Attributes (Metadata)

### Basic Info
```java
BasicFileAttributes attrs = Files.readAttributes(path, BasicFileAttributes.class);

attrs.creationTime();
attrs.lastAccessTime();
attrs.lastModifiedTime();
attrs.size();
attrs.isDirectory();
attrs.isRegularFile();
```

---

### POSIX (Linux/macOS)
```java
PosixFileAttributes attrs = Files.readAttributes(path, PosixFileAttributes.class);

attrs.owner();      // "alice"
attrs.group();      // "staff"
attrs.permissions(); // {OWNER_READ, OWNER_WRITE, ...}
```

---

### DOS (Windows)
```java
DosFileAttributes attrs = Files.readAttributes(path, DosFileAttributes.class);
attrs.isReadOnly();
attrs.isHidden();
attrs.isArchive();
```

---

### Custom Attributes (Extended)
```java
UserDefinedFileAttributeView view = 
    Files.getFileAttributeView(path, UserDefinedFileAttributeView.class);

view.write("department", Charset.defaultCharset().encode("HR"));
```

> **Use case**: Tag files with `priority=high`, `project=alpha`

## 9. Asynchronous File I/O

> **For ultra-high performance** (e.g., web servers)

```java
AsynchronousFileChannel channel = 
    AsynchronousFileChannel.open(path, StandardOpenOption.READ);

ByteBuffer buffer = ByteBuffer.allocate(1024);

channel.read(buffer, 0, null, new CompletionHandler<Integer, Object>() {
    @Override
    public void completed(Integer bytesRead, Object attachment) {
        buffer.flip();
        byte[] data = new byte[bytesRead];
        buffer.get(data);
        System.out.println(new String(data));
    }

    @Override
    public void failed(Throwable exc, Object attachment) {
        exc.printStackTrace();
    }
});
```

> **Like Node.js** — non-blocking, event-driven

## 10. Best Practices (Must Remember!)

| Rule | Why |
|------|-----|
| Always use `try-with-resources` | Auto-close streams |
| Use `Paths.get()` not `new File()` | Safer, modern |
| Prefer `Files.lines()` over `readAllLines()` | Memory efficient |
| Use `StandardCopyOption.REPLACE_EXISTING` | Avoid `FileAlreadyExistsException` |
| `normalize()` user input paths | Prevent `../` attacks |

## 11. Full Working Example: Log File Analyzer

```java
public class LogAnalyzer {
    public static void main(String[] args) throws IOException {
        Path logDir = Paths.get("logs");

        Files.walk(logDir)
             .filter(Files::isRegularFile)
             .filter(p -> p.toString().endsWith(".log"))
             .forEach(LogAnalyzer::analyze);
    }

    private static void analyze(Path logFile) {
        System.out.println("Analyzing: " + logFile.getFileName());

        try (Stream<String> lines = Files.lines(logFile)) {
            long errors = lines
                .filter(line -> line.contains("ERROR"))
                .count();

            System.out.println("  → Errors: " + errors);
        } catch (IOException e) {
            System.err.println("  → Failed: " + e.getMessage());
        }
    }
}
```

## Summary Table: NIO.2 vs Old `File`

| Feature | `java.io.File` | `java.nio.file` |
|-------|----------------|-----------------|
| Immutable path | No | Yes (`Path`) |
| Safe file ops | Risky | Yes (`Files`) |
| Tree walking | Manual | Yes (`walk`, `find`) |
| Async I/O | No | Yes |
| Symbolic links | No | Yes |
| Atomic move | No | Yes |
| Metadata | Limited | Yes Full |

---

## Final Tips to Master NIO.2

1. **Never use `new File()` again** → Use `Paths.get()`
2. **Always close with `try(Stream)`**
3. **Use `walk()` + `filter()`** like SQL for files
4. **Practice**: Build a **file duplicate finder**
5. **Bonus**: Try `WatchService` to monitor folder changes
