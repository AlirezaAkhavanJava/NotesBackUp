
## What is a Microservice?

Imagine you’re building a toy castle. Instead of making one giant castle that’s hard to move or fix, you build it with small, separate pieces (like towers, walls, and gates). Each piece works on its own but connects with others to form the castle. If one piece breaks, you fix just that piece without touching the rest.

A **microservice** is like one of those small pieces. It’s a small, independent part of an application that does one specific job (e.g., handling user logins, processing payments). These microservices work together to make a complete app. Each microservice:

- Runs independently.
- Communicates with others over a network (e.g., HTTP/REST APIs).
- Can be built, updated, or scaled separately.

**Why use microservices?**

- Easier to fix or update small parts.
- Different teams can work on different microservices.
- You can scale only the parts that need more power (e.g., add more payment servers during a sale).

**Spring Boot** is a Java framework that makes it easy to build microservices quickly. It simplifies setup and coding.

**Spring Cloud** is a set of tools built on top of Spring Boot to make microservices work better together. It helps with things like:

- Finding microservices (service discovery).
- Load balancing.
- Managing configurations.
- Handling failures.

## Step 1: Basic Concepts

### Monolith vs. Microservices

- **Monolith**: One big application with all features in one codebase. Hard to scale or change.
- **Microservices**: Many small apps, each doing one thing, talking to each other. Easier to manage but needs coordination.

### Key Terms

- **Service Discovery**: A way for microservices to find each other (like a phonebook for services).
- **API Gateway**: A single entry point for all client requests, routing them to the right microservice.
- **Load Balancing**: Distributing work across multiple instances of a microservice to avoid overloading.
- **Configuration Management**: Storing settings (e.g., database URLs) in one place for all microservices.
- **Circuit Breaker**: A way to stop requests to a failing microservice to prevent crashes.

## Step 2: Setting Up a Simple Microservice with Spring Boot

Let’s create a basic Spring Boot microservice. We’ll build a “User Service” that returns a list of users.

### Prerequisites

- Java 17+ installed.
- Maven or Gradle (we’ll use Maven).
- An IDE like IntelliJ or VS Code.

### Create a Spring Boot Project

1. Go to [Spring Initializr](https://start.spring.io/).
2. Choose:
    - Project: Maven
    - Language: Java
    - Spring Boot: Latest stable version (e.g., 3.2.x)
    - Dependencies: **Spring Web**
3. Download and open in your IDE.

### Basic Code

Let’s create a simple REST controller.

```java
// UserController.java
package com.example.userservice;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class UserController {

    @GetMapping("/users")
    public String getUsers() {
        return "List of users: Alice, Bob, Charlie";
    }
}
```

### Key Annotations

- **`@RestController`**: Marks this class as a REST API controller. It handles HTTP requests and returns data (like JSON).
- **`@GetMapping`**: Maps HTTP GET requests to this method. For example, `/users` triggers `getUsers()`.

### Run the Microservice

1. Run the `UserServiceApplication.java` (generated by Spring Initializr).
2. Open `http://localhost:8080/users` in a browser. You’ll see: `List of users: Alice, Bob, Charlie`.

This is a single microservice. Now let’s add Spring Cloud to make it part of a microservices system.

## Step 3: Adding Spring Cloud Features

Let’s add **Spring Cloud** to make our microservices system smarter. We’ll cover:

1. Service Discovery (with Eureka).
2. Centralized Configuration (with Spring Cloud Config).
3. API Gateway (with Spring Cloud Gateway).
4. Circuit Breaker (with Resilience4j).

### 1. Service Discovery with Eureka

Microservices need to find each other. **Eureka** is a service registry where microservices register themselves.

#### Step 1: Create a Eureka Server

1. Create a new Spring Boot project with dependency: **Spring Cloud Netflix Eureka Server**.
2. Add this to `application.properties`:

```properties
server.port=8761
eureka.client.register-with-eureka=false
eureka.client.fetch-registry=false
```

3. Add `@EnableEurekaServer` to the main class:

```java
// EurekaServerApplication.java
package com.example.eurekaserver;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.cloud.netflix.eureka.server.EnableEurekaServer;

@SpringBootApplication
@EnableEurekaServer
public class EurekaServerApplication {
    public static void main(String[] args) {
        SpringApplication.run(EurekaServerApplication.class, args);
    }
}
```

4. Run the Eureka server. Open `http://localhost:8761` to see the Eureka dashboard.

#### Step 2: Register User Service with Eureka

1. Add dependency to User Service: **Spring Cloud Netflix Eureka Client**.
2. Update `application.properties`:

```properties
spring.application.name=user-service
eureka.client.service-url.defaultZone=http://localhost:8761/eureka/
```

3. Add `@EnableDiscoveryClient` to `UserServiceApplication.java`:

```java
// UserServiceApplication.java
package com.example.userservice;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.cloud.client.discovery.EnableDiscoveryClient;

@SpringBootApplication
@EnableDiscoveryClient
public class UserServiceApplication {
    public static void main(String[] args) {
        SpringApplication.run(UserServiceApplication.class, args);
    }
}
```

4. Run both Eureka Server and User Service. Check `http://localhost:8761`—you’ll see `user-service` registered.

**What’s happening?**

- The User Service registers with Eureka.
- Other microservices can now find it by name (`user-service`) instead of a hardcoded URL.

### 2. Centralized Configuration with Spring Cloud Config

Microservices need configurations (e.g., database URLs). Instead of hardcoding them, store them in a central place with **Spring Cloud Config**.

#### Step 1: Create a Config Server

1. Create a new Spring Boot project with dependency: **Spring Cloud Config Server**.
2. Add to `application.properties`:

```properties
server.port=8888
spring.cloud.config.server.git.uri=https://github.com/your-repo/config-repo
```

3. Create a Git repository (`config-repo`) with a file named `user-service.yml`:

```yaml
# config-repo/user-service.yml
greeting: Hello from Config Server!
```

4. Add `@EnableConfigServer` to the main class:

```java
// ConfigServerApplication.java
package com.example.configserver;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.cloud.config.server.EnableConfigServer;

@SpringBootApplication
@EnableConfigServer
public class ConfigServerApplication {
    public static void main(String[] args) {
        SpringApplication.run(ConfigServerApplication.class, args);
    }
}
```

5. Run the Config Server.

#### Step 2: Connect User Service to Config Server

1. Add dependency to User Service: **Spring Cloud Starter Config**.
2. Create `bootstrap.properties` in User Service:

```properties
spring.cloud.config.uri=http://localhost:8888
spring.application.name=user-service
```

3. Update `UserController.java` to use the config:

```java
// UserController.java
package com.example.userservice;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class UserController {

    @Value("${greeting}")
    private String greeting;

    @GetMapping("/users")
    public String getUsers() {
        return greeting + " List of users: Alice, Bob, Charlie";
    }
}
```

4. Run Config Server, Eureka Server, and User Service. Visit `http://localhost:8080/users`. You’ll see: `Hello from Config Server! List of users: Alice, Bob, Charlie`.

**What’s happening?**

- The User Service fetches its configuration (`greeting`) from the Config Server.
- You can update `user-service.yml` in Git, and the Config Server will serve the new config.

### 3. API Gateway with Spring Cloud Gateway

Clients shouldn’t call microservices directly. An **API Gateway** routes requests to the right microservice.

#### Step 1: Create a Gateway Service

1. Create a new Spring Boot project with dependencies: **Spring Cloud Gateway**, **Spring Cloud Netflix Eureka Client**.
2. Add to `application.properties`:

```properties
spring.application.name=gateway-service
server.port=8080
eureka.client.service-url.defaultZone=http://localhost:8761/eureka/
spring.cloud.gateway.routes[0].id=user-service
spring.cloud.gateway.routes[0].uri=lb://user-service
spring.cloud.gateway.routes[0].predicates[0]=Path=/users/**
```

3. Add `@EnableDiscoveryClient` to the main class:

```java
// GatewayApplication.java
package com.example.gatewayservice;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.cloud.client.discovery.EnableDiscoveryClient;

@SpringBootApplication
@EnableDiscoveryClient
public class GatewayApplication {
    public static void main(String[] args) {
        SpringApplication.run(GatewayApplication.class, args);
    }
}
```

4. Run Eureka Server, User Service, and Gateway Service. Visit `http://localhost:8080/users`. The Gateway routes the request to the User Service.

**What’s happening?**

- The Gateway uses Eureka to find `user-service`.
- The `lb://user-service` means load-balanced routing to the User Service.

### 4. Circuit Breaker with Resilience4j

If a microservice fails, we don’t want the whole system to crash. A **Circuit Breaker** stops requests to a failing service.

#### Step 1: Add Resilience4j to User Service

1. Add dependency: **Spring Boot Starter AOP**, **Spring Cloud Starter Circuitbreaker Resilience4j**.
2. Update `UserController.java`:

```java
// UserController.java
package com.example.userservice;

import io.github.resilience4j.circuitbreaker.annotation.CircuitBreaker;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class UserController {

    @Value("${greeting}")
    private String greeting;

    @GetMapping("/users")
    @CircuitBreaker(name = "userService", fallbackMethod = "fallback")
    public String getUsers() {
        // Simulate failure (uncomment to test)
        // if (true) throw new RuntimeException("Service down!");
        return greeting + " List of users: Alice, Bob, Charlie";
    }

    public String fallback(Throwable t) {
        return "Fallback: Service is down, try again later!";
    }
}
```

3. Add to `application.properties`:

```properties
resilience4j.circuitbreaker.instances.userService.failure-rate-threshold=50
resilience4j.circuitbreaker.instances.userService.minimum-number-of-calls=5
```

4. Run the services. If the `/users` endpoint fails (e.g., uncomment the exception), you’ll see the fallback message.

**What’s happening?**

- If the User Service fails too often, the Circuit Breaker “opens” and calls the `fallback` method instead.

## Step 4: Advanced Concepts

### Load Balancing with Spring Cloud LoadBalancer

When you have multiple instances of a microservice, **Spring Cloud LoadBalancer** distributes requests. It’s already used in the Gateway (`lb://user-service`).

To test:

1. Run multiple instances of User Service on different ports (e.g., 8081, 8082).
2. Update `application.properties` for each instance:

```properties
server.port=8081 # or 8082
```

3. The Gateway will automatically balance requests across instances.

### Distributed Tracing with Spring Cloud Sleuth and Zipkin

Track requests as they flow through microservices.

1. Add dependency to all services: **Spring Cloud Starter Sleuth**, **Spring Cloud Starter Zipkin**.
2. Run a Zipkin server (e.g., via Docker: `docker run -d -p 9411:9411 openzipkin/zipkin`).
3. Add to `application.properties`:

```properties
spring.zipkin.base-url=http://localhost:9411
spring.sleuth.sampler.probability=1.0
```

4. Make requests through the Gateway. Check `http://localhost:9411` to see request traces.

### Event-Driven Microservices with Spring Cloud Stream

Microservices can communicate using messages (e.g., via Kafka or RabbitMQ).

1. Add dependency: **Spring Cloud Starter Stream Kafka**.
2. Configure Kafka in `application.properties`:

```properties
spring.cloud.stream.bindings.userChannel-out-0.destination=user-topic
spring.cloud.stream.bindings.userChannel-in-0.destination=user-topic
```

3. Create a message producer and consumer:

```java
// UserService.java
package com.example.userservice;

import org.springframework.cloud.stream.function.StreamBridge;
import org.springframework.context.annotation.Bean;
import org.springframework.stereotype.Service;

import java.util.function.Consumer;

@Service
public class UserService {

    private final StreamBridge streamBridge;

    public UserService(StreamBridge streamBridge) {
        this.streamBridge = streamBridge;
    }

    public void sendMessage(String message) {
        streamBridge.send("userChannel-out-0", message);
    }

    @Bean
    public Consumer<String> userChannel() {
        return message -> System.out.println("Received: " + message);
    }
}
```

4. Update `UserController.java` to send a message:

```java
@GetMapping("/send")
public String sendMessage() {
    userService.sendMessage("New user added!");
    return "Message sent!";
}
```

5. Run a Kafka server (e.g., via Docker). Test by calling `http://localhost:8080/send`.

## Step 5: Putting It All Together

Here’s how the system looks:

- **Eureka Server**: Registers all microservices.
- **Config Server**: Provides centralized configurations.
- **Gateway Service**: Routes client requests.
- **User Service**: Handles user-related logic with circuit breakers and messaging.
- **Zipkin**: Traces requests.
- **Kafka**: Handles event-driven communication.

To run:

1. Start Kafka and Zipkin (via Docker).
2. Start Eureka Server (`port 8761`).
3. Start Config Server (`port 8888`).
4. Start User Service (`port 8081`).
5. Start Gateway Service (`port 8080`).
6. Test via `http://localhost:8080/users`.

## Key Annotations Summary

- **`@SpringBootApplication`**: Marks the main class of a Spring Boot app.
- **`@RestController`**: Creates a REST API controller.
- **`@GetMapping`**, **`@PostMapping`**, etc.: Maps HTTP requests to methods.
- **`@EnableEurekaServer`**: Sets up a Eureka server.
- **`@EnableDiscoveryClient`**: Allows a service to register with Eureka.
- **`@EnableConfigServer`**: Sets up a Config Server.
- **`@Value`**: Injects configuration properties.
- **`@CircuitBreaker`**: Adds circuit breaker logic.

## Tips for Advanced Usage

- **Scaling**: Run multiple instances of a microservice and let the Gateway load-balance.
- **Security**: Add Spring Security for authentication/authorization.
- **Database**: Use Spring Data JPA for database access in microservices.
- **Testing**: Use `@SpringBootTest` for integration tests.
- **Monitoring**: Use Spring Boot Actuator for health checks (`/actuator/health`).
