
# Java 25 — New Features (LTS Release)

Java 25 (released September 2025) is a **Long-Term Support (LTS)** release — the LTS following Java 21, and the most recent LTS as of your current setup. This is genuinely current, cutting-edge Java — several features you've seen as "preview" in Java 21 have now progressed further, and several brand-new ones landed.

---

## 1. Compact Source Files and Instance Main Methods (JEP 512) — finalized

**Definition:** lets you write and run a simple Java program **without** the traditional ceremony (`public class`, `public static void main(String[] args)`) — aimed specifically at beginners and small scripts.

```java
// A COMPLETE, valid Java 25 program — no class declaration needed at all!
void main() {
    System.out.println("Hello, Alireza!");
}
```

Compare to what you've been writing throughout this entire conversation:

```java
// Traditional — required in Java 24 and earlier
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Alireza!");
    }
}
```

**Problem it solves:** for a total beginner, having to understand `public`, `class`, `static`, `void`, and `String[] args` just to print "Hello World" is a genuinely steep, mostly-irrelevant first hurdle — none of those concepts matter yet on day one. This feature lets you start with the **one line that actually matters** and grow into full class-based syntax later, once those concepts are actually relevant to what you're writing.

```java
// You can also skip main() entirely for trivial single-expression-style scripts:
void main() {
    var name = "Alireza";
    System.out.println("Hello, " + name);
}
```

**Important:** this doesn't change or weaken the language for real projects — `public class ... { public static void main(...) }` still works exactly as before, and is still what you'll use for any real Spring Boot application. This feature exists specifically for scripts, quick tests, and teaching contexts.

You can run it directly, without even compiling separately first:

```bash
java Hello.java
```

## 2. Module Import Declarations (JEP 511) — finalized

**Definition:** lets you import **an entire module's exported packages** in one line, instead of importing each package individually.

```java
// Before — importing several packages from the same module, one by one
import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;
import java.io.IOException;

// Java 25 — import an entire module at once
import module java.base;
```

**Problem it solves:** for programs (especially the compact source files from feature #1) that use many different pieces of the standard library, manually importing each individual package is friction that provides little real benefit for casual/learning code. `import module java.base` pulls in everything commonly needed (`java.util`, `java.io`, `java.util.stream`, etc.) in one line.

```java
import module java.base;

void main() {
    List<String> names = List.of("Alireza", "Sara");
    var upper = names.stream().map(String::toUpperCase).toList();
    System.out.println(upper);
}
```

**Worth noting:** this pairs directly with feature #1 — together, they're specifically designed to make a beginner's _first_ Java programs dramatically less boilerplate-heavy, exactly matching the learning journey you've been on throughout this entire conversation.

## 3. Flexible Constructor Bodies (JEP 513) — finalized

**Definition:** allows statements to appear in a constructor **before** the mandatory call to `super(...)` or `this(...)` — as long as those statements don't reference the instance being constructed (`this`) in a way that would be unsafe before initialization.

```java
class Vehicle {
    Vehicle(String type) {
        System.out.println("Creating a " + type);
    }
}

class Car extends Vehicle {
    Car(int doors) {
        // Java 25: validation logic BEFORE calling super() is now allowed
        if (doors <= 0) {
            throw new IllegalArgumentException("Doors must be positive");
        }
        super("Car"); // super() call no longer has to be the ABSOLUTE first statement
        System.out.println("Doors: " + doors);
    }
}
```

**Problem it solves:** before this, `super(...)`/`this(...)` **had** to be the literal first statement in a constructor — meaning you couldn't validate arguments or compute a derived value _before_ calling the parent constructor, even when that validation had nothing to do with the object's own state yet.

```java
// Before Java 25 — validation had to happen AWKWARDLY, often via a static helper method
class Car extends Vehicle {
    Car(int doors) {
        super(validateDoors(doors)); // forced into a workaround — a static method just to validate first
    }
    private static String validateDoors(int doors) {
        if (doors <= 0) throw new IllegalArgumentException("Doors must be positive");
        return "Car";
    }
}
```

This connects directly to the custom exceptions tutorial's constructor patterns — validating constructor arguments is exactly the scenario this feature makes more natural to express.

## 4. Scoped Values (JEP 506) — finalized

**Definition:** a modern alternative to `ThreadLocal` for sharing **immutable** data implicitly down a call chain — particularly designed to work well with **virtual threads** (from the Java 21 tutorial).

```java
import java.lang.ScopedValue;

final static ScopedValue<String> CURRENT_USER = ScopedValue.newInstance();

void handleRequest() {
    ScopedValue.where(CURRENT_USER, "Alireza").run(() -> {
        processRequest(); // CURRENT_USER is accessible anywhere in this call chain
    });
}

void processRequest() {
    System.out.println("Processing for: " + CURRENT_USER.get()); // "Alireza"
}
```

**Problem it solves:** `ThreadLocal` (the traditional way to do this) has real problems in a virtual-threads world (from the Java 21 threads tutorial) — it's **mutable** (any code anywhere can silently change it), it can **leak memory** if not explicitly cleaned up, and it doesn't compose well with the massive numbers of short-lived virtual threads Java 21+ encourages you to create.

```java
// The old ThreadLocal way — mutable, needs manual cleanup
ThreadLocal<String> currentUser = new ThreadLocal<>();
currentUser.set("Alireza");
try {
    processRequest();
} finally {
    currentUser.remove(); // MUST remember to clean up, or it leaks across thread-pool reuse
}
```

`ScopedValue` is **immutable** for the duration of its scope, automatically bound only within the specific `run()`/`call()` block, and automatically cleaned up when that block exits — no manual `remove()` needed, and no risk of another part of the code accidentally mutating it mid-flight. This is a genuinely important companion feature to virtual threads for real server-side (Spring Boot–style) code.

## 5. Primitive Types in Patterns, `instanceof`, and `switch` (JEP 507) — third preview

**Definition:** extends the pattern matching you learned in the Java 21 tutorial to work with **primitive types** (`int`, `double`, etc.), not just reference types.

```java
Object obj = 42;

// Now works directly with primitive patterns (still PREVIEW in Java 25)
String result = switch (obj) {
    case int i when i > 100 -> "Big int";
    case int i -> "Small int";
    case double d -> "Double: " + d;
    default -> "Other";
};
```

**Problem it solves:** the pattern matching from Java 21 (`case Integer i ->`) only worked with **boxed** reference types (`Integer`, not raw `int`) — extending it to primitives directly removes an artificial inconsistency, and connects to the boxing/unboxing overhead concerns raised in the `Predicate`/`Function` primitive-specialization tutorials.

**Status:** still a **preview feature** in Java 25 (third round of preview) — worth knowing about, but not yet something to rely on as permanently stable syntax.

## 6. Structured Concurrency (JEP 505) — fifth preview

Already introduced in the Java 21 tutorial as a preview feature — as of Java 25, it's now in its **fifth preview round**, meaning it's been refined multiple times based on feedback but **still hasn't finalized**.

```java
try (var scope = StructuredTaskScope.open()) { // API shape has evolved across preview rounds
    var user = scope.fork(() -> fetchUser());
    var order = scope.fork(() -> fetchOrder());
    scope.join();
    System.out.println(user.get() + ", " + order.get());
}
```

**Why it's taken this long:** this connects directly to the "preview features can still change" caution flagged repeatedly throughout the concurrency tutorials — structured concurrency's exact API has genuinely been reworked across several JDK releases based on real-world developer feedback, which is precisely what the preview process exists to allow. If you're using this in Java 25, check the current JDK documentation for the exact API shape, since it has changed release to release.

## 7. Compact Object Headers (JEP 519) — finalized

**Definition:** reduces the size of the **object header** (the internal metadata every Java object carries — mentioned back in the marker interfaces tutorial) from 96–128 bits down to **64 bits** on 64-bit platforms.

**Problem it solves:** every single object in the JVM heap carries this header overhead, regardless of how small the object's actual data is — for applications creating huge numbers of small objects (common in data-heavy or high-throughput applications), this overhead adds up meaningfully across millions/billions of objects. Shrinking it directly reduces overall heap memory usage and improves cache efficiency (connecting to the cache-locality discussion from the `ArrayList` vs `LinkedList` tutorial) across the board, with no code changes required on your part.

**Relevance:** a JVM-internal performance improvement — you get this benefit automatically just by running on Java 25, no code changes needed.

---

## 8. Generational Shenandoah (JEP 521) — finalized

**Definition:** brings the same "generational" young/old object separation strategy — already applied to ZGC in Java 21 — to the **Shenandoah** garbage collector (another low-pause-time GC, an alternative to ZGC).

**Problem it solves:** the exact same problem Generational ZGC (Java 21 tutorial) solved, just for people who specifically use Shenandoah instead of ZGC — most objects die young, so separating generations lets the collector focus effort more efficiently, reducing pause times and CPU overhead.

---

## 9. Key Derivation Function API (JEP 510) — finalized

**Definition:** a new `javax.crypto` API specifically for **KDFs** (Key Derivation Functions) — cryptographic algorithms that derive one or more secret keys from a shared secret (connecting to the KEM API from Java 21, and the `javax.crypto` mention in the Java API reference tutorial).

```java
KDF kdf = KDF.getInstance("HKDF-SHA256");
// used to derive cryptographic keys from a shared secret, in a standardized way
```

**Relevance:** niche, security/cryptography-focused — not something typical Spring Boot application code touches directly, but part of the JDK's continued modernization of its cryptography APIs (alongside JEP 452's KEM API from Java 21).

---

## 10. PEM Encodings of Cryptographic Objects (JEP 470) — preview

**Definition:** a preview API for reading and writing **PEM-encoded** cryptographic objects (keys, certificates) — PEM being the common base64-text format you'll recognize from SSL/TLS certificates (`-----BEGIN CERTIFICATE-----`).

```java
PEMEncoder encoder = PEMEncoder.of();
String pem = encoder.encodeToString(someKey); // still PREVIEW in Java 25
```

**Relevance:** if you ever work with TLS certificates or key management in Java (relevant to Spring Boot's HTTPS configuration), this is worth knowing exists, though it's still preview.

---

## 11. Removal of the 32-bit x86 Port (JEP 503)

**Definition:** Java 25 formally **removes** support for 32-bit x86 systems entirely — the JDK now only targets 64-bit platforms.

**Relevance:** purely a platform-support matter, reflecting that 32-bit x86 hardware is now genuinely obsolete for running modern JVMs — not something that affects your Debian 13 setup (which runs on 64-bit x86-64).

## Where this closes the loop for your learning path

Given that you're learning Java and Spring Boot **right now**, on Java 25 (the current LTS), features #1–#4 are genuinely worth internalizing as "how modern Java looks" — you may see tutorials/examples online still using the old `public class`/`public static void main` style (which remains completely valid and is what you'll use for any real multi-file Spring Boot project), but simple scripts and learning exercises can now legitimately look like the minimal `void main()` examples shown here. **Scoped Values** and the continued evolution of **structured concurrency** are both direct extensions of the virtual-threads foundation from Java 21 — exactly the trajectory the concurrency tutorials throughout this conversation have been building toward.
