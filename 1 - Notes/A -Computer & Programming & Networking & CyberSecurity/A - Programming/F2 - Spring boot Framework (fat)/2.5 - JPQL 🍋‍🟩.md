

> **JPQL (Java Persistence Query Language)** is a **query language for JPA that works with entities, not tables**.

SQL thinks in tables and columns.  
JPQL thinks in **Java objects and fields**.

Example contrast:

SQL:

```sql
SELECT * FROM users WHERE name = 'Ethan';
```

JPQL:

```java
SELECT u FROM User u WHERE u.name = 'Ethan';
```

Key idea:

- `User` → **entity class**, not table name
    
- `u.name` → **field**, not column
    
- Result → **User objects**, not rows
    

Why JPQL exists:

- Database-independent
    
- Object-oriented
    
- Integrated with the persistence context
    

What happens under the hood:

- You write JPQL
    
- **Hibernate (persistence provider)** converts it to SQL
    
- SQL runs on the database
    
- Results come back as managed entities
    

One-line truth:

> **JPQL is SQL for objects.**

Reality check (important):

- JPQL ≠ SQL
    
- JPQL cannot use DB-specific features
    
- For native power → **native SQL queries**
    

Quick self-check to lock it in:  
If you rename a table but keep the entity the same — **JPQL still works**.  
If you rename the entity or field — **JPQL breaks**.
