
1. **The view definition is saved permanently**
    

`CREATE VIEW top_ten_students AS SELECT *  FROM student WHERE mark > 9.0 ORDER BY mark DESC LIMIT 10;`

- PostgreSQL **remembers this query**.
    
- You can query `top_ten_students` anytime, and it will always use this query to show data.
    

2. **The data shown by the view is dynamic**
    

- If you **insert, update, or delete** rows in the `student` table, the results of the view **change automatically**.
    
- The view itself **doesn’t store the rows**, it just runs your query each time.
    

3. **The “code” of the view is saved**
    

- The `SELECT * FROM student WHERE mark > 9.0 ORDER BY mark DESC LIMIT 10` is stored in the database as the view definition.
    
- That’s why every time you do:
    

`SELECT * FROM top_ten_students;`

- PostgreSQL executes that same query on the current `student` table and returns the top 10 students at that moment.
