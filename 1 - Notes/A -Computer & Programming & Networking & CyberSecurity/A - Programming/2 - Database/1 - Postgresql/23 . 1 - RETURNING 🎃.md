

# **RETURNING in SQL (PostgreSQL)**

### **1. Definition**

`RETURNING` is a PostgreSQL clause that lets you **get back the data of the row(s) you just inserted, updated, or deleted** — without running another query.

---

## **2. What it returns**

You can return:

- A specific column (`RETURNING id`)
    
- Multiple columns (`RETURNING id, name`)
    
- All columns (`RETURNING *`)
    

---

## **3. Why it’s useful**

Because you often need to know:

- What **ID** was generated
    
- What **values** ended up in the DB (especially defaults, triggers, sequences)
    

It saves you from writing a second `SELECT` after the operation.

---

## **4. Examples**

### **INSERT with RETURNING**

```sql
INSERT INTO students_info (name, address, age, student_global_id)
VALUES ('Bill Cosby', 'Abadan', 560, 1200)
RETURNING *;
```

### **UPDATE with RETURNING**

```sql
UPDATE students_info
SET age = 40
WHERE student_global_id = 1200
RETURNING name, age;
```

### **DELETE with RETURNING**

```sql
DELETE FROM students_info
WHERE student_global_id = 1200
RETURNING *;
```

---

## **5. Workflow (clear)**

1. Run INSERT / UPDATE / DELETE
    
2. DB modifies the row
    
3. DB immediately returns the requested data
    
4. You read it in your application
