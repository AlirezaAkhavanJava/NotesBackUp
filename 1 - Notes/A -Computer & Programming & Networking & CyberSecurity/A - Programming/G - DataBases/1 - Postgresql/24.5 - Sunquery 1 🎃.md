
In PostgreSQL, a **subquery** is a **query inside another query**. It’s also called an **inner query** or **nested query**.

- The **outer query** uses the result of the subquery to filter, compare, or calculate data.
    
- Subqueries can appear in **SELECT, FROM, or WHERE** clauses.
    

---

### 🔹 Examples

**1. Subquery in WHERE**

```sql
-- Find students with marks higher than the class average
SELECT name, mark
FROM student
WHERE mark > (SELECT AVG(mark) FROM student);
```

- `(SELECT AVG(mark) FROM student)` is the subquery.
    
- Outer query selects students **above average**.
    

---

**2. Subquery in FROM**

```sql
-- Get the top 3 marks first, then calculate their average
SELECT AVG(mark) AS top_avg
FROM (
    SELECT mark
    FROM student
    ORDER BY mark DESC
    LIMIT 3
) AS top_students;
```

- Subquery returns the top 3 marks.
    
- Outer query calculates the average of these marks.
    

---

**3. Subquery in SELECT**

```sql
-- Show each student with the average mark of all students
SELECT name, mark, (SELECT AVG(mark) FROM student) AS class_avg
FROM student;
```

---

### 💡 Key Notes

- Subqueries **run first**, then their result is used by the outer query.
    
- Can return **single value**, **multiple rows**, or **tables**, depending on context.
    
- Sometimes you can replace subqueries with **JOINs** for performance.
    



---

## 🧱 **Rules for Subqueries**

1. **Placement Rules**
    
    - **WHERE clause** → returns value(s) for filtering.
        
    - **FROM clause** → acts like a temporary table for the outer query.
        
    - **SELECT clause** → returns a value for each row.
        
    
    Example:
    
    ```sql
    SELECT name
    FROM student
    WHERE mark > (SELECT AVG(mark) FROM student);
    ```
    
2. **Return Type Rules**
    
    - **Single value** → use `=` or `<`, `>` (scalar subquery).
        
        ```sql
        WHERE mark = (SELECT MAX(mark) FROM student)
        ```
        
    - **Multiple rows** → use `IN`, `ANY`, `ALL`.
        
        ```sql
        WHERE id IN (SELECT student_id FROM top_students)
        ```
        
    - **Multiple columns** → use `ROW()` or subquery in `FROM`.
        
3. **Nesting Limit**
    
    - PostgreSQL supports **deeply nested subqueries**, but too many layers can hurt performance.
        
4. **Correlation**
    
    - **Uncorrelated** → independent subquery.
        
    - **Correlated** → refers to outer query columns.
        
        ```sql
        SELECT s1.name
        FROM student s1
        WHERE s1.mark > (SELECT AVG(s2.mark) FROM student s2 WHERE s2.department = s1.department);
        ```
        
5. **Performance**
    
    - Subqueries are **executed first** (unless optimized).
        
    - Sometimes a `JOIN` is faster than a subquery.
        

---

## 💡 **When to Use Subqueries**

1. **Filtering based on aggregation**
    
    - e.g., find students above average mark.
        
2. **Simplifying complex queries**
    
    - Break queries into smaller, readable parts.
        
3. **Temporary calculations**
    
    - e.g., get top N records first, then calculate something on them.
        
4. **Isolation from main table**
    
    - e.g., calculate something once without affecting main query logic.
        

---

**Rule of thumb:**

- Use a subquery when you **need a value or set of values that depends on another query**.
    
- If you just need to combine tables, a **JOIN** is usually better for performance.
