


An **execution plan** (also called a query plan) in PostgreSQL is the detailed strategy generated by the query planner/optimizer for executing a SQL statement. It describes the specific operations PostgreSQL will perform to retrieve or modify data, such as how tables are scanned (e.g., sequential scan, index scan), how joins are performed (e.g., nested loop, hash join, merge join), sorting, aggregation, and more.

The planner evaluates multiple possible plans and selects the one with the lowest estimated **cost** (a unitless measure based on factors like disk I/O, CPU usage, estimated row counts, and table statistics). This ensures efficient execution, especially for complex queries involving joins, filters, or large datasets.

### How to View an Execution Plan
Use the `EXPLAIN` command before your SQL query:

- `EXPLAIN <query>`: Shows the **estimated** plan with costs, estimated rows, and node types (no execution occurs).
- `EXPLAIN ANALYZE <query>`: Executes the query and shows **actual** runtime statistics (rows returned, time spent per node, loops). Useful for diagnosing performance but modifies data for INSERT/UPDATE/DELETE (wrap in a transaction and rollback if needed).
- Common options: `BUFFERS` (shows cache/disk hits), `VERBOSE` (more details), `FORMAT JSON` (machine-readable output).

### Example Output
For a simple query:

```
EXPLAIN SELECT * FROM users WHERE id = 1;
```

Typical output:

```
QUERY PLAN
------------------------------------------------------------
Index Scan using users_pkey on users  (cost=0.28..8.30 rows=1 width=126)
  Index Cond: (id = 1)
```

- **Node type**: Index Scan (efficient, uses primary key index).
- **Cost**: Startup cost .. total cost (lower is better).
- **Rows**: Estimated rows returned.

With `EXPLAIN ANALYZE`:

```
Index Scan using users_pkey on users  (cost=0.28..8.30 rows=1 width=126) (actual time=0.021..0.034 rows=1 loops=1)
  Index Cond: (id = 1)
Planning Time: 0.068 ms
Execution Time: 0.105 ms
```

This compares estimates vs. actuals, revealing inaccuracies in statistics or opportunities for optimization (e.g., adding indexes to avoid sequential scans).

### Key Plan Nodes
- **Scans**: Seq Scan (full table read), Index Scan, Bitmap Index Scan.
- **Joins**: Nested Loop, Hash Join, Merge Join.
- **Other**: Sort, Aggregate, Hash, GroupAggregate.

Plans are tree-structured (indented in text output), with the root node at the top. Tools like explain.dalibo.com or pev (Postgres Explain Visualizer) can visualize them graphically.

Execution plans are crucial for query tuning—slow queries often show expensive sequential scans or high-cost joins that can be improved with indexes, updated statistics (`ANALYZE`), or query rewrites. For full details, see the official PostgreSQL documentation on [Using EXPLAIN](https://www.postgresql.org/docs/current/using-explain.html).
