

# Learn Git: `.gitignore` Patterns  
*Boot.dev Lesson – Full Teaching Guide*

---

## Objective
By the end of this lesson, you’ll be able to:
- Write powerful `.gitignore` rules using **wildcards**, **rooted paths**, **negation**, and **comments**.
- Understand **why order matters**.
- Predict exactly which files Git will ignore.

---

## 1. Wildcards: `*`

> The `*` matches **any sequence of characters**, **except `/`**.

### Example:
```gitignore
*.txt
```
Ignores:
- `note.txt`
- `data.txt`
- `src/utils/helper.txt`

Does **not** ignore:
- `txtfiles/data.txt` → `*` doesn't match `/`

> Think of `*` as “anything in this folder level”.

---

## 2. Rooted Patterns: Start with `/`

> A pattern starting with `/` is **anchored to the folder containing the `.gitignore` file**.

### Example:
```gitignore
/main.py
```
Ignores **only**:
- `main.py` in the **root directory**

Does **not** ignore:
- `src/main.py`
- `app/main.py`

> Use `/` when you want precision.

---

## 3. Negation: `!`

> Prefix with `!` to **un-ignore** a file that matches a previous rule.

### Example:
```gitignore
*.txt
!important.txt
```
Result:
- All `.txt` files ignored
- `important.txt` is **tracked** (even if it ends in `.txt`)

> Negation **overrides** earlier ignore rules.

---

## 4. Comments: `#`

> Start a line with `#` to add notes — Git ignores it.

### Example:
```gitignore
# Ignore all log files
*.log
```

> Great for team clarity.

---

## 5. Order Matters! (Critical Rule)

> **Later rules override earlier ones.**

### Example:
```gitignore
temp/*
!temp/keep.me
```

Ignores everything in `temp/`  
**Except** `temp/keep.me` → **saved by negation**

### But if reversed:
```gitignore
!temp/keep.me
temp/*
```
`keep.me` is **ignored** — the `temp/*` rule comes last and wins.

> **Always put specific rules (like `!`) AFTER general ones.**

# Assignment: Analyze This `.gitignore`

```gitignore
# *.js

*.txt
!names.txt

/src/main.py

content.md
```

---

## Step-by-Step Breakdown

| Line | Pattern | Meaning |
|------|--------|--------|
| 1 | `# *.js` | **Comment** → no effect |
| 2 | `*.txt` | Ignore **all** `.txt` files anywhere |
| 3 | `!names.txt` | **Un-ignore** `names.txt` (anywhere) |
| 4 | `/src/main.py` | Ignore **only** `src/main.py` in root |
| 5 | `content.md` | Ignore **every** `content.md` anywhere |

# Quiz: Will These Files Be Ignored?

| File Path | Ignored? | Why? |
|---------|----------|------|
| `readme.txt` | Yes | `*.txt` |
| `names.txt` | No | `!names.txt` overrides |
| `data/names.txt` | No | Negation applies recursively |
| `src/main.py` | Yes | `/src/main.py` (rooted) |
| `app/src/main.py` | No | Not in root `src/` |
| `content.md` | Yes | Exact match anywhere |
| `docs/content.md` | Yes | Pattern is relative |
| `script.js` | No | Only commented, no rule |
| `temp.log` | No | No `.log` rule |

# Pro Tips

| Tip | Example |
|-----|--------|
| Use `**` for deep matching | `**/*.tmp` → any `.tmp` anywhere |
| Ignore folder | `build/` |
| Ignore all in folder except one | `logs/*` <br> `!logs/.gitkeep` |
| Check what’s ignored | `git check-ignore -v filename` |

---

# Final Summary

| Pattern | Meaning |
|--------|--------|
| `*.txt` | All `.txt` files |
| `/file.py` | Only root-level file |
| `!file.txt` | Don’t ignore this one |
| `# comment` | Human note |
| `dir/` | Entire directory |
| Later beats earlier | Order is king |
