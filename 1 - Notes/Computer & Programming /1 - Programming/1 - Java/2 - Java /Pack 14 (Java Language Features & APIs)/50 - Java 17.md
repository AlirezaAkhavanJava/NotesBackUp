
# Java 17 — New Features (LTS Release)

Java 17 (released September 2021) is a **Long-Term Support (LTS)** release — the LTS between Java 11 and Java 21, finalizing several features that had been brewing across multiple prior versions. Several of these were already referenced in passing throughout this conversation (sealed classes, pattern matching for `instanceof`, text blocks) — this tutorial defines each properly.

---

## 1. Sealed Classes (JEP 409) — finalized

Already used in the exceptions tutorial's advanced section — full definition here.

**Definition:** a `sealed` class or interface **restricts which other classes/interfaces are allowed to extend or implement it** — you explicitly list every permitted subtype with `permits`.

```java
sealed abstract class Shape permits Circle, Square, Triangle {}

final class Circle extends Shape {
    double radius;
    Circle(double radius) { this.radius = radius; }
}

final class Square extends Shape {
    double side;
    Square(double side) { this.side = side; }
}

final class Triangle extends Shape {
    double base, height;
    Triangle(double base, double height) { this.base = base; this.height = height; }
}
```

```java
// Attempting to add a new, unlisted subtype elsewhere in the codebase:
final class Hexagon extends Shape {} // COMPILE ERROR — Hexagon is not in the permits list
```

**The problem it solves:** normal (non-sealed) inheritance lets **anyone, anywhere** extend your class — which means code that pattern-matches over all possible subtypes can never be certain it's handled every case, since a new subtype could always be added later, anywhere, by anyone.

```java
// With a sealed hierarchy, the compiler KNOWS these are the only 3 possible subtypes
double area(Shape shape) {
    return switch (shape) {
        case Circle c -> Math.PI * c.radius * c.radius;
        case Square s -> s.side * s.side;
        case Triangle t -> 0.5 * t.base * t.height;
        // NO default needed — compiler verifies all 3 permitted subtypes are covered
    };
}
```

**Subtypes of a sealed class must be one of:** `final` (no further extension allowed), `sealed` (further restricted extension), or `non-sealed` (opens it back up to unrestricted extension) — every subtype must explicitly declare which.

```java
sealed class Shape permits Circle, Square {}
non-sealed class Square extends Shape {} // explicitly reopens extension for Square specifically
class BigSquare extends Square {}           // now allowed, since Square opted back into normal inheritance
```

## 2. Pattern Matching for `instanceof` (JEP 394) — finalized

Already referenced in the exceptions tutorial — the foundational feature pattern matching for `switch` (Java 21) later builds on.

**Definition:** combines an `instanceof` check and a cast into a single step, binding a new variable automatically when the check succeeds.

```java
Object obj = "Hello";

// Before Java 17 — check, then manually cast
if (obj instanceof String) {
    String s = (String) obj; // separate, manual cast needed
    System.out.println(s.length());
}

// Java 17+ — check AND cast in one step
if (obj instanceof String s) {
    System.out.println(s.length()); // `s` is already a String, no separate cast
}
```

**Problem it solves:** eliminates the redundant, error-prone "check the type, then immediately cast to that exact same type" pattern that was previously unavoidable boilerplate every time you needed to safely downcast.

```java
// Combines naturally with && for more complex conditions
if (obj instanceof String s && s.length() > 5) {
    System.out.println("Long string: " + s);
}
```

## 3. Text Blocks (JEP 378) — finalized

**Definition:** a multi-line string literal, delimited by `"""` (three double quotes), that preserves formatting without needing escape characters or `+` concatenation for line breaks.

```java
// Before text blocks — awkward, hard to read
String html = "<html>\n" +
              "    <body>\n" +
              "        <p>Hello, World</p>\n" +
              "    </body>\n" +
              "</html>";

// With text blocks — clean, readable, matches actual output shape
String html = """
    <html>
        <body>
            <p>Hello, World</p>
        </body>
    </html>
    """;
```

**Problem it solves:** embedding multi-line content (HTML, JSON, SQL queries) in Java source code previously required either ugly `\n` + `+` concatenation chains, or external files — text blocks let the string's on-screen shape directly match its intended output shape, dramatically improving readability for embedded structured text.

```java
String json = """
    {
        "name": "Alireza",
        "age": 25
    }
    """;
```

**Escaping still works when genuinely needed:**

```java
String withQuotes = """
    She said "hello" to me.
    """; // no escaping needed for regular quotes inside a text block

String withBackslash = """
    Line one \
    continues here without a line break""";
```

This connects directly to the IO tutorials' file-writing examples — text blocks are frequently used together with `Files.writeString()` for generating templated content (config files, email templates).

## 4. Enhanced Pseudo-Random Number Generators (JEP 356) — finalized

**Definition:** a new interface hierarchy (`RandomGenerator`) unifying and expanding Java's random number generation APIs, adding several new, higher-quality algorithms beyond the legacy `java.util.Random`.

```java
import java.util.random.RandomGenerator;

RandomGenerator generator = RandomGenerator.of("L64X128MixRandom"); // one of several NEW algorithms
int value = generator.nextInt(100);
```

**Problem it solves:** the old `java.util.Random` (and `SecureRandom`, `ThreadLocalRandom`) had **no shared interface** — code written against one couldn't easily be swapped to use another. `RandomGenerator` provides one common interface across all of them (old and new), plus adds several modern, statistically superior algorithms not previously available in the JDK at all.

```java
// Legacy classes still work, but now also implement the new shared interface
RandomGenerator legacy = new java.util.Random();
RandomGenerator secure = new java.security.SecureRandom();
```

## 5. Foreign Function & Memory API (JEP 412, incubator) — incubating

**Definition:** an early-stage API allowing Java code to call **native (non-Java) code** and access **off-heap memory** directly, without needing the older, more cumbersome JNI (Java Native Interface).

```java
// Simplified illustration — actual API evolved significantly in later JDKs before finalizing
```

**Problem it aims to solve:** JNI (the traditional way to call C/C++ libraries from Java) is notoriously verbose, unsafe, and error-prone. This new API aims to provide a safer, more ergonomic way to interoperate with native code and memory — directly connects to the "Foreign Function & Memory API" mention in the earlier IO tutorial (which noted it finalized in Java 22, well after this Java 17 incubating stage).

**Status in Java 17:** still an **incubator module** — an even earlier stage than "preview," meaning the API was actively expected to change significantly before finalizing (which it later did, in Java 22).

## 6. Deprecation and removal of the Applet API (JEP 398) — deprecated for removal

**Definition:** the `java.applet` package (for building browser-embedded Java applets — a technology from the 1990s web) was formally marked deprecated **for removal**, reflecting that applets had been obsolete for years (no modern browser supports the Java plugin they required).

**Relevance:** purely historical — not something you'd encounter in any current Java/Spring Boot work, included here only because it's part of what Java 17 officially changed.

---

## 7. Strong encapsulation of JDK internals (JEP 403) — finalized

**Definition:** most internal JDK APIs (`sun.*` packages, and similar) are now **strongly encapsulated** by default — code outside the JDK itself can no longer access them via reflection unless explicitly permitted with command-line flags.

**Problem it solves:** for years, some libraries/frameworks reached into JDK internal implementation details via reflection (bypassing the intended public API) — a fragile practice, since those internals could change between JDK versions without warning, breaking such libraries unpredictably. Strong encapsulation makes this practice much harder to do accidentally, pushing the ecosystem toward using only officially supported, stable public APIs.

**Relevance:** mostly an under-the-hood change; occasionally surfaces as a compatibility issue when upgrading older libraries/frameworks to run on Java 17+, since some legacy tools genuinely did rely on now-blocked internal access.

---

## 8. macOS/AArch64 (Apple Silicon) Port (JEP 391) — finalized

**Definition:** native JDK support for Apple Silicon (M1/M2, ARM64-based) Macs.

**Relevance:** purely a platform-support matter — if you're on Debian 13 (as your setup is), this doesn't affect you directly, but it's a notable Java 17 milestone for the broader ecosystem.

## Where this fits with everything you've learned

Java 17 is genuinely the **foundation** that Java 21's headline features build directly on top of: **pattern matching for `instanceof`** (Java 17) is the exact mechanism that **pattern matching for `switch`** (Java 21) generalizes; **sealed classes** (Java 17) are what makes Java 21's **exhaustive switch pattern matching** actually verifiable by the compiler (as shown in the sealed-exception-hierarchy example from the exceptions tutorial). **Text blocks** connect directly to the file-writing examples across the I/O tutorials. If you're targeting Java 17 as an LTS baseline for a Spring Boot project (a very common real-world choice, alongside Java 21), these are the modern-Java features you'd actually have available and should be using.
