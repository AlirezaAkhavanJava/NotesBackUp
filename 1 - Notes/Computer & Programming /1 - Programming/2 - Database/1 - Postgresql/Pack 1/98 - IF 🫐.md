
Below is a **complete, authoritative guide** to **`IF` in PostgreSQL** — covering **all forms**, **syntax**, **rules**, **use cases**, **performance**, and **senior-level patterns**.

---

## 1. There Is **No `IF` Statement** in PostgreSQL SQL

> **PostgreSQL SQL does not have `IF ... THEN ... ELSE` like procedural languages.**

But PostgreSQL provides **three equivalent constructs**:

| Construct | Where Used | Purpose |
|---------|-----------|--------|
| `CASE` | `SELECT`, `WHERE`, `ORDER BY`, etc. | **Conditional logic in expressions** |
| `IF` | **PL/pgSQL only** (`DO`, functions, triggers) | **Procedural control flow** |
| `COALESCE`, `NULLIF` | Any expression | **Simple conditional defaults** |

---

## 2. `CASE` — The SQL `IF`

### Syntax

```sql
CASE
    WHEN condition1 THEN result1
    WHEN condition2 THEN result2
    ...
    ELSE default_result
END
```

```sql
CASE expression
    WHEN value1 THEN result1
    WHEN value2 THEN result2
    ...
    ELSE default_result
END
```

---

### Examples

#### 1. **Simple `CASE` (like `SWITCH`)**
```sql
SELECT 
    employee_id,
    salary,
    CASE salary
        WHEN > 100000 THEN 'Executive'
        WHEN > 70000 THEN 'Senior'
        WHEN > 40000 THEN 'Mid'
        ELSE 'Junior'
    END AS tier
FROM employees;
```

#### 2. **Searched `CASE` (like `IF-ELSE`)**
```sql
SELECT 
    name,
    CASE 
        WHEN salary > 100000 THEN 'Bonus: ' || salary * 0.20
        WHEN salary > 70000 THEN 'Bonus: ' || salary * 0.15
        ELSE 'No bonus'
    END AS bonus_info
FROM employees;
```

#### 3. **`CASE` in `WHERE`**
```sql
SELECT *
FROM orders
WHERE 
    CASE 
        WHEN customer_type = 'VIP' THEN order_date >= '2025-01-01'
        ELSE order_date >= '2024-01-01'
    END;
```

#### 4. **`CASE` in `ORDER BY`**
```sql
SELECT name, salary, department
FROM employees
ORDER BY 
    CASE 
        WHEN department = 'Sales' THEN 1
        WHEN department = 'Engineering' THEN 2
        ELSE 3
    END,
    salary DESC;
```

## 3. `IF` in **PL/pgSQL** (Functions, Triggers, `DO` blocks)

### Syntax

```sql
IF condition THEN
    -- statements
ELSIF condition2 THEN
    -- statements
ELSE
    -- statements
END IF;
```

### Example: Function with `IF`

```sql
CREATE OR REPLACE FUNCTION get_employee_tier(sal NUMERIC)
RETURNS TEXT AS $$
BEGIN
    IF sal > 100000 THEN
        RETURN 'Executive';
    ELSIF sal > 70000 THEN
        RETURN 'Senior';
    ELSIF sal > 40000 THEN
        RETURN 'Mid';
    ELSE
        RETURN 'Junior';
    END IF;
END;
$$ LANGUAGE plpgsql;
```

### Example: `DO` Block with `IF`

```sql
DO $$
DECLARE
    avg_sal NUMERIC;
BEGIN
    SELECT AVG(salary) INTO avg_sal FROM employees;

    IF avg_sal > 80000 THEN
        RAISE NOTICE 'High salary company!';
    ELSE
        RAISE NOTICE 'Average company.';
    END IF;
END $$;
```

## 4. `COALESCE` and `NULLIF` — Lightweight `IF`

| Function | Purpose | Example |
|--------|--------|--------|
| `COALESCE(expr1, expr2, ...)` | Return **first non-NULL** | `COALESCE(phone, 'N/A')` |
| `NULLIF(expr1, expr2)` | Return `NULL` if equal | `NULLIF(commission, 0)` → avoids divide-by-zero |

```sql
-- Avoid divide by zero
SELECT 
    sales,
    commission,
    sales / NULLIF(commission, 0) AS ratio
FROM reps;
```

## 5. Performance & Indexing

| Construct | Indexable? | Notes |
|---------|-----------|-------|
| `CASE` in `SELECT` | Yes | No impact on plan |
| `CASE` in `WHERE` | **No** (unless sargable) | Avoid non-sargable `CASE` |
| `CASE` in `ORDER BY` | Yes | Planner handles |
| `IF` in PL/pgSQL | — | Procedural, no index |

### **Bad**: Non-sargable `CASE` in `WHERE`
```sql
-- Prevents index use
WHERE CASE WHEN active THEN created_date > '2025-01-01' ELSE true END;
```

### **Good**: Push logic into indexed columns
```sql
WHERE (NOT active) OR (active AND created_date > '2025-01-01')
```

## 6. Senior-Level Patterns

### 1. **Dynamic SQL with `CASE`**
```sql
SELECT *
FROM orders
WHERE 
    customer_id = $1
    AND order_date >= 
        CASE 
            WHEN $2 = 'VIP' THEN '2025-01-01'
            ELSE '2024-01-01'
        END;
```

### 2. **Conditional Aggregation**
```sql
SELECT 
    department,
    COUNT(*) AS total,
    COUNT(CASE WHEN salary > 100000 THEN 1 END) AS executives
FROM employees
GROUP BY department;
```

### 3. **Upsert with `CASE`**
```sql
INSERT INTO employee_stats (emp_id, tier)
VALUES (123, 'Senior')
ON CONFLICT (emp_id) DO UPDATE
SET tier = 
    CASE 
        WHEN EXCLUDED.tier = 'Executive' THEN 'Executive'
        ELSE employee_stats.tier
    END;
```

### 4. **Boolean `CASE` for Flags**
```sql
SELECT 
    name,
    salary,
    (CASE WHEN salary > (SELECT AVG(salary) FROM employees) THEN true ELSE false END) AS above_avg
FROM employees;
```
→ Simplify with:
```sql
salary > (SELECT AVG(salary) FROM employees) AS above_avg
```

## 7. Common Pitfalls

| Mistake | Fix |
|-------|-----|
| Using `IF` in SQL | Use `CASE` |
| `CASE` with non-deterministic functions | May skew results |
| `NULL` handling in `CASE` | Use `COALESCE` inside |
| Overusing `CASE` in `WHERE` | Rewrite as `OR`/`AND` |

---

## 8. Cheat Sheet

```sql
-- SQL IF → CASE
CASE WHEN x > 10 THEN 'High' ELSE 'Low' END

-- Simple CASE
CASE status WHEN 'A' THEN 'Active' ELSE 'Inactive' END

-- PL/pgSQL IF
IF x > 10 THEN ... END IF;

-- Default value
COALESCE(col, 'unknown')

-- Avoid divide by zero
col / NULLIF(denom, 0)
```

## Decision Table: When to Use What

| You Want… | Use |
|---------|-----|
| Conditional **value** in `SELECT` | `CASE` |
| Conditional **filter** | `CASE` or boolean logic |
| Conditional **control flow** in function | `IF` in `PL/pgSQL` |
| First non-null | `COALESCE` |
| Avoid divide-by-zero | `NULLIF` |

## Final Summary

| Feature | SQL | PL/pgSQL |
|-------|-----|----------|
| `IF` | Not exists | Yes |
| Conditional logic | `CASE` | `IF` / `CASE` |
| Default value | `COALESCE` | `:=` or `COALESCE` |
| Performance | Fast in `SELECT` | Slower (procedural) |
